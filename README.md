# ЛР №6. Знакомство с promise и fetch, сборка клиентской части.

## Цель

Лабораторная состоит из 2-х частей:

- **Часть 1.** Изменение механизма взаимодействия с внешним API: в прошлой
  лабораторной работе использовался `XMLHttpRequest`, в этой — современный
  метод `fetch`. Все вызовы переведены на `async/await` + `Promise`.
- **Часть 2.** Сборка клиентской части приложения: «сбилдить» фронтенд (карточки
  «Эволюция») с помощью `Vite`, а в серверную часть (ЛР №4) добавить раздачу
  `public/` в качестве статики, чтобы избавиться от CORS.

## План

**Часть 1:**
1. Введение в `Promise`.
2. Использование `Promise`.
3. `async/await` в JS.
4. `fetch` — пример использования.

**Часть 2:**
1. Сборка клиентской части через `Vite`.
2. Раздача фронтенда в качестве статики из ветки `lab4-expressjs`.

## Команды

```bash
npm install         # установить зависимости (vite, three, bootstrap)
npm run dev         # vite dev-сервер на http://localhost:5173 (CORS — через расширение)
npm run build       # сборка в ./public
npm run preview     # просмотр production-сборки
```

## Что в этой ветке (`lab6-fetch`)

- Только **исходники** фронтенда. На показе **этот код не запускается**.
- Сборка `npm run build` кладёт результат в `./public/` (он в `.gitignore`).
- Содержимое `./public/` копируется в ветку `lab4-expressjs` как `public/`,
  и бэкенд раздаёт его через `express.static` — карточки и API работают на
  одном домене, CORS не нужен.

## Что изменилось относительно ЛР №5

| ЛР №5                           | ЛР №6                                    |
|---------------------------------|------------------------------------------|
| `XMLHttpRequest` + коллбеки     | `fetch` + `async/await`                  |
| `modules/ajax.js`               | `modules/api.js`                         |
| Только `GET`/`DELETE`           | + `POST` (создание) и `PATCH` (правка)   |
| Форма без кнопки «Сохранить»    | Кнопка **Сохранить** работает            |
| Запросы напрямую с Live Server  | Сборка `Vite` → раздача из бэка          |
| Обход CORS через расширение     | Один домен, CORS не нужен                |
